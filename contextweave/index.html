01 / 问题记忆为什么不只是检索
长期 AI 的难题，不只是“能不能搜回来”，还包括它现在是否仍然成立、该不该被说出来，以及它与过去发生过什么关系。

长期交互的问题，
不只是遗忘。

一次普通检索，可以把旧文本找回来；真正的连续性，需要系统理解这段历史现在意味着什么。

01有效性这条信息现在还成立吗？
02关联性它与哪些历史事件属于同一个模式？
03时机这一次值得主动提起吗？
设计原则连续性优先于堆积
目标不是建一个更大的记忆仓库，而是控制什么值得继续影响未来。
02 / 记忆演化记忆生命周期

一次事件，
只是一份证据。

长期画像来自反复出现、彼此印证的历史信息，而不是一次即时判断。

原始事件 → 证据 → 模式 / 事件弧 → 滚动画像记忆会被强化、修订、衰减或归档，而不是永久以原样堆积。
原始事件自然对话、行为与状态变化
提取证据实体、时间、状态、结果
关联模式 / 事件弧重复关系与连续事件链
修订滚动画像持续更新的长期认知
为什么重要
“记住”不是在某一天做一次标签，而是允许未来的新证据推翻今天的结论。
03 / 召回距离T0 · T1 · T2

记忆离当前问题，
也有“距离”。

ContextWeave 不把所有相关历史一次性塞进上下文，而是按候选记忆与当前意图之间的关联距离分层。距离越远，需要越明确的关系链和更严格的筛选。

T0

直接命中

当前问题与某条记忆、实体或明确线索直接相关。优先进入候选池，不需要借助额外关系跳转。

T1

一跳关联

当前问题没有直接命中旧记忆，但可以通过一个共享实体、关系或事件链把它连接回来。

T2

受限二跳

需要经过两层关系才能到达的候选。只有在确实能补足上下文时才继续展开，避免召回无限扩散。

T0 / T1 / T2 描述的是“召回时离当前意图有多远”。它们与“事件如何逐渐形成长期画像”的记忆演化链是两套不同维度。
设计目的
既允许模型沿关系找到“没有直接说出来、但确实相关”的历史，又给远距离关联设置边界。
04 / 召回交付排序与策略

被找到的记忆，
也不一定会被使用。

不同距离产生候选后，还要继续经过相关度、置信度、上下文预算与策略筛选，最后只把真正有用的内容交付给当前任务。

01当前意图理解这一轮真正需要什么
02候选池实体 / 关键词 / 向量 / 关系
03重新排序相关度与置信度
04策略筛选预算、冷却与角色
05上下文交付必要记忆进入当前交互
关键区别
召回距离决定“去哪里找”；排序与策略决定“找到了以后，要不要真的带进当前上下文”。
05 / 可运行原型公开记忆沙盒

产品逻辑之外，
它也真的跑着。

公开 Sandbox 使用完全脱敏的样板数据，访客可以写入临时记忆、换一种问法召回，并查看一次召回为什么成立。

可运行原型写入 → 召回 → 轨迹把“系统真的工作”放到次级入口，而不是让调试字段占据主叙事。
数据隔离完全脱敏不连接私人记忆与真实对话。
体验打开公开 Sandbox ↗进入可运行原型
负责内容
从问题定义、系统结构、交互规则到测试验证与持续迭代，形成完整产品闭环。
