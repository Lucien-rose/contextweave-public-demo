CONTEXTWEAVE · MEMORY ORCHESTRATION

把分散上下文，织成长期连续性。

ContextWeave 是一个面向长期 AI 交互的上下文记忆编排系统原型。重点不在“存得更多”，而在于让记忆可以被累积、修订、衰减，并在真正相关时重新进入当前对话。

← 返回项目入口
01 · PROBLEM

长期交互的问题，不只是遗忘。

普通检索可以找回文本，却很难处理“这条信息现在还成立吗”“它和过去哪些事件属于同一个模式”“这一次值得主动提起吗”。

ContextWeave 把问题拆成两条链路：记忆如何演化，以及当前意图下哪些上下文值得被召回。

02 · MEMORY EVOLUTION

记忆不是堆积，而是一条流。

一次事件只是一份证据。重复、关联与后续结果，才逐步形成可解释的长期画像。

01Raw Event自然对话与日常事件
02Evidence实体、时间、状态与结果
03Arc / Pattern重复关系与可解释模式
04Rolling Profile强化、修正、衰减、归档
03 · CONTEXT DELIVERY

记住，不等于每次都说出来。

召回从候选池开始，经由相关度、置信度、上下文预算与策略筛选，最后只把真正有用的内容交付给当前任务。

Current Intent理解当前问题
Candidate Pool实体 / 关键词 / 向量 / 关系
Rerank相关度与置信度
Policy冷却、预算与角色
Delivery交付必要上下文
04 · WORKING PROTOTYPE

产品逻辑之外，它也真的跑着。

公开 Sandbox 使用完全脱敏的样板数据，让访客写入临时记忆、换一种问法召回，并查看一次召回为什么成立。它被保留为“可运行证据”，而不再承担主展示页的信息架构。

05 · PRODUCT EXPRESSION

同一套记忆思想，如何进入具体生活？

ContextWeave 是底层能力；Familiar 是它进入真实产品场景之后的表达。

在 Familiar 中，事件不再以系统字段出现，而是变成一句自然对话、一次食欲变化、一份医嘱和一次个性化决策。
