01 / PROBLEMWhy memory is more than retrieval
长期 AI 的难题，不只是“能不能搜回来”，还包括它现在是否仍然成立、该不该被说出来，以及它与过去发生过什么关系。

长期交互的问题，
不只是遗忘。

一次普通检索，可以把旧文本找回来；真正的连续性，需要系统理解这段历史现在意味着什么。

01Validity这条信息现在还成立吗？
02Relationship它与哪些历史事件属于同一个模式？
03Timing这一次值得主动提起吗？
DESIGN PRINCIPLEContinuity over accumulation
目标不是建一个更大的记忆仓库，而是控制什么值得继续影响未来。
02 / EVOLUTIONMemory lifecycle

一次事件，
只是一份证据。

长期画像来自反复出现、彼此印证的历史信息，而不是一次即时判断。

Event → Evidence → Pattern / Arc → Rolling Profile记忆会被强化、修订、衰减或归档，而不是永久以原样堆积。
RAWEvent自然对话、行为与状态变化
EXTRACTEvidence实体、时间、状态、结果
RELATEPattern / Arc重复关系与连续事件链
REVISERolling Profile持续更新的长期认知
WHY IT MATTERS
“记住”不是在某一天做一次标签，而是允许未来的新证据推翻今天的结论。
03 / DELIVERYRecall distance & policy

记住，
不等于每次都说出来。

召回从候选池开始，经由相关度、置信度、上下文预算与策略筛选，最后只把真正有用的内容交付给当前任务。

01Current Intent理解当前问题
02Candidate Pool实体 / FTS / 向量 / 关系
03Rerank相关度与置信度
04Policy预算、冷却与角色
05Delivery必要上下文进入当前交互
ARCHITECTURE NOTE
T0 / T1 / T2 属于召回距离：描述候选记忆离当前意图有多远，而不是记忆本身如何演化。
04 / PROOFWorking public sandbox

产品逻辑之外，
它也真的跑着。

公开 Sandbox 使用完全脱敏的样板数据，访客可以写入临时记忆、换一种问法召回，并查看一次召回为什么成立。

LIVE PROTOTYPEWrite → Recall → Trace把“系统真的工作”放到次级入口，而不是让调试字段占据主叙事。
PRIVACYIsolated data不连接私人记忆与真实对话。
OPENLaunch Public Sandbox ↗进入可运行原型
ROLE
从问题定义、系统结构、交互规则到测试验证与持续迭代，形成完整产品闭环。
